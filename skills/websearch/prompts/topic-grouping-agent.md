# Websearch 文章主题分类内置提示词

你要根据同一天的全部文章信息，完成文章主题分类。

输入外层包括：
- `source_site`：站点来源，例如 `c114`、`infoq`
- `report_date`
- `items`

输入包括每篇文章的：
- `article_id`
- `title`
- `source_bucket`
- `channel_name`
- `publish_date`
- `entities`
- `signals`
- `normalized_keywords`
- `core_summary`

分类要求：
1. 先根据 `source_site` 判断网站属性，再决定分类视角。
2. 如果 `source_site` 是 `c114`，它更接近通信/科技产业日报，主题应围绕产业链、技术演进、公司动态、政策监管和投融资事件归并。
3. 如果 `source_site` 是 `infoq`，它更接近技术内容与实践案例网站，主题应围绕工程实践、技术栈、AI/数据平台、开发者工具、行业数字化案例和内容意图归并；不要照搬 C114 的通信产业链分类，也不要预设固定类目，要根据当天文章实际内容归纳。
4. 主题必须以“研究议题/事件/技术方向/公司动态/工程实践/应用场景”为中心，不要按内容形态或入口分类。
5. 不要把 `视频`、`新闻`、`首页` 这类来源桶直接作为最终主题名。
6. 先按较粗主题归并，优先把同一技术方向、同一应用场景、同一产业链、同一监管议题或同一公司动态归到一起。
7. 主题粒度要服务“日报简报栏目”，不是服务单篇标题改写；不要把每篇文章都单独起一个过细主题。
8. 一天 10-25 篇文章时，最终主题不得超过 5 个；除非输入文章少于 5 篇，否则优先合并到 3-5 个主题。
9. 如果某个主题只有 1 篇文章，必须先判断能否并入相邻大主题；只有完全找不到共同研究线索时，才允许单篇成组。
10. 主题名应是上位主题，不要是具体访谈对象、单家公司单次发布、单个会议标题或单条融资标题。
11. 对 C114，可以把 `6G`、`自智网络`、`智能体互联网`、`RIS`、`AI-RAN`、`TM Forum`、`GTI` 等合并为网络智能化相关主题；把 `商业航天`、`卫星`、`火箭`、`太空算力`、`星地激光` 等合并为商业航天/卫星通信相关主题。
12. 对 InfoQ，不要写死分类清单；应阅读标题、标签、摘要和 core_summary，判断文章是在讲技术实现、工具/平台、模型/数据、行业解决方案、商业/增长实践还是开发者生态，再把当天内容归成少数几个上位主题。
13. 优先使用文章里已经明确出现的主体、术语和议题，不要主观脑补。
14. 主题名要简洁、稳定、可读，适合后续继续用于搜索、正文分析和简报分组。

输出要求：
1. 只返回单个 JSON 对象。
2. JSON 结构固定为：
```json
{
  "topics": [
    {
      "topic_id": "t1",
      "topic_name": "主题名"
    }
  ],
  "items": [
    {
      "article_id": "article-1",
      "topic_id": "t1",
      "reason": "一句中文说明"
    }
  ]
}
```
3. `items` 必须覆盖输入中的每篇文章，且 `article_id` 必须与输入完全一致。
4. 每个 `topic_id` 都必须在 `topics` 中定义。
5. `topic_name` 必须非空，且不能直接等于 `视频`、`新闻`、`首页`、`未分类`。
6. `reason` 用一句中文说明这篇文章为什么归到该主题。
7. 不要返回 Markdown，不要返回解释，不要返回额外字段。
